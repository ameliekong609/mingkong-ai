# AGENTS.md

## Project purpose

Build mingkong.ai, a professional portfolio website for Dr Ming Kong.

The website should position Ming as an enterprise applied AI leader specialising in:

- enterprise AI adoption
- agentic AI and multi-agent systems
- production AI engineering
- controlled digital-worker architectures
- customer-facing AI transformation
- cloud AI across Google Cloud, AWS and Azure

This is not a generic consultant website and should not read like a traditional corporate CV.

## Source of truth

Before changing content or architecture, read:

- `docs/personal-brand.md`
- `docs/website-brief.md`
- `docs/content-inventory.md`
- `docs/design-direction.md`
- `docs/project-case-studies.md`
- `docs/cv-source.md`

Do not invent clients, metrics, roles, technologies or production claims.

Where client names are not explicitly approved, use anonymised descriptions such as:

- major Australian telecommunications provider
- major Australian bank
- major Australian energy infrastructure provider
- national Australian retailer
- major retail and hospitality group

## Core positioning

The primary positioning is:

> Designing and deploying the next generation of enterprise AI systems — from production multi-agent platforms to controlled autonomous digital workers.

Ming should be presented as someone who combines:

1. hands-on AI engineering
2. enterprise architecture
3. customer adoption and transformation
4. executive communication
5. technical innovation

Avoid presenting her primarily as:

- a product manager
- a generic management consultant
- a data scientist focused only on modelling
- a no-code or prompt-only AI practitioner

## Writing style

Use concise, technically credible language.

Prefer:

- designed
- architected
- deployed
- evaluated
- integrated
- orchestrated
- productionised
- guided adoption
- removed blockers
- established controls

Avoid exaggerated claims such as:

- revolutionary
- world-leading
- unparalleled
- groundbreaking

Do not call a system production-ready unless the source material states that it was deployed or productionised.

## Technical credibility

Clearly distinguish:

- deterministic workflows
- agentic planning
- tool-calling
- multi-agent orchestration
- reflective review
- self-correction
- human approval
- evidence grounding
- release controls

Do not describe simple sequential LLM calls as autonomous agents.

## Design principles

The site should feel:

- premium
- intelligent
- modern
- technically sophisticated
- restrained
- credible to Google, AWS, Mistral, Anthropic and enterprise AI leaders

Use strong typography, generous spacing and selective blue accents.

Avoid:

- generic AI brain imagery
- neon cyberpunk visuals
- excessive gradients
- stock-photo consulting imagery
- cluttered dashboards
- buzzword-heavy animations

## Engineering workflow

Before implementation:

1. inspect the repository
2. read all files under `docs/`
3. propose an implementation plan
4. identify unresolved content or asset gaps
5. build in small reviewable stages

After each meaningful change:

- run linting
- run tests
- build the site
- check mobile and desktop layouts
- report files changed and remaining issues

Do not overwrite approved copy without explaining the change.
